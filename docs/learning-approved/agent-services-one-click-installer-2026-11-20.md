# SWADEBASE Agent Services — one-click installer specification
Date: 2026-11-20. Status: approved product direction / implementation specification ONLY. No site installs, public page deploys, paid renders or agent execution activated by this document.
Goal: one verified registered-site selector -> inspect actual source, Site Bible, brand, service adapters and roles -> select engine (MausBot, Rakazo or bounded hybrid) -> configure agents and each capability separately -> generate impeccable-reviewed site-specific agent services landing page and context-aware HyperFrames/Remotion explainer -> run end-to-end sandbox tests -> preview -> explicit site-scoped approval -> deploy, verify and rollback.
Authority: canonical SWADEBASE registry / auth / central encrypted vault / Stripe / permissions / approval history / SSS Brain; isolated runtime for MausBot on SWADEBASE4 (candidate, not yet proven live), Rakazo on SWADEBASE2 (running, shared execution not yet certified); prevent duplicate databases and uncontrolled secret distribution.
Site enrollment workflow: (1) select site ID from existing mail_machine_registered_sites; (2) resolve actual production URL, git repo, hosting and editable source; (3) detect supported industry package and current features (unknown until verified); (4) choose provider, agent list, roles, ownership, private/shared computer tier, memory, voice, optional dedicated phone, email, browser, SSH, vault, billing, integrations; (5) per-capability on/off and customer-tier entitlements; (6) apply server-side policy at auth, dispatch and credential broker; (7) generate original site-specific page with Impeccable checker, accessibility and preservation tests; (8) author 60-90s original explainer storyboard in site brand, render through existing HyperFrames/Remotion/FFmpeg adapter only when actually supported; (9) synth voice/media first from existing owned assets and free/CPU operations; (10) sandbox/check screenshots and audio; (11) owner approval to publish; (12) feature probes, metrics and receipts.
Required server policy dimensions: site_id, tenant_id, agent_id, engine, capability, enabled, runtime_ready, plan_entitlement, explicit_approval, allowed_operations, origins, expiry, budget, concurrency, storage/call quotas, secret references (never raw), actor, version, audit, rollback. Effective permission is intersection of site enabled, agent enabled, account entitlement, current runtime health and operation grant; deny by default. Turning off phone halts outgoing/incoming agent features and prevents new calls (without losing configuration); computer off revokes new leases and pauses existing sessions safely; vault off prevents new secret use, not simply hiding UI. Preserve owner access and reversible settings.
