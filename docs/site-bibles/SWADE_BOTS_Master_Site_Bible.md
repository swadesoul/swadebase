### Conversation intelligence
For a bot configured with Together as provider, the protected POST /adapters/api/swade-bots/message invokes existing MiniMaxAI/MiniMax-M3.1-Flash via SWADEBASE Developer Studio createTextProvider. System context uses saved bot identity, assigned site, role and owner instructions. Includes bounded short recent history scoped to active conversation ID; allows natural typos and follow-up questions. Model receives NO tools. Existing provider ledger handles reserve/settle, verified rate cards and controlled call timeout; no automatic retry. Per-reply budget ceiling USD 0.001, extra bot-specific daily ceiling USD 0.05, existing global Together daily spending ceiling USD 1; the most restrictive guard applies. For bot roster and ontology counts the assistant uses local SQL metadata, avoiding model expense. Other providers remain unconnected; local basic reference mode is available. AI responds to user questions but cannot independently operate external apps.

### Owner-only voice
Existing SWADE Voice Service at Hostinger's private endpoint 172.16.0.1:8790 reused without buying additional voice APIs. POST /adapters/api/swade-bots/voice/transcribe uses Whisper CPU (short microphone audio uploaded as form, converted by existing ffmpeg to 16k mono WAV), returns text; POST /adapters/api/swade-bots/voice/speak uses Kokoro CPU (voice kokoro:af_alloy) to return MP3 audio. Both enforce owner identity/role, CSRF, per-hour quota, concurrent job bound, size limits and temporary buffers; no customer audio is deliberately stored. iPad Safari uses MediaRecorder and browser getUserMedia; tap mic to record, tap stop to transcribe, send to intelligent chat and play spoken reply. This is turn-based speech conversation, NOT continuous full-duplex Grok Live voice, no avatar lip sync and no device camera/video. No browser secrets sent to model/voice.

### Stored conversations
Additive schema migration: swadebase_ops.swade_bots_conversations table, nullable swade_bots_messages.conversation_id, owner+bot indexes and grant to swadebase_adapters; existing 2 messages migrated into an 'Earlier conversation'. POST /threads/new creates independent thread, GET /threads lists owner threads, GET /messages filters by thread, POST /message stores owner+bot+thread messages and updates title. Existing null legacy handling is preserved for compatibility. Never delete stored history just to create a new conversation.

Autonomous Rakazo/SWADEBASE-2 workers are NOT connected to this conversational front-end; site health reports and public/customer data remain separately permissioned. ## Voice conversation update: persistent orb, three-second silence, two-minute turns and hands-free barge-in — 2026-11-14 UTC

Founder requested (a) keep the orb visible when conversations start, (b) reduce the gap between conversation turns with automatic submission after roughly 3 seconds of silence, (c) increase a fixed 30-second speaking limit to 120 seconds, and (d) allow interruptions BY THE FOUNDER SPEAKING without tapping, including when Chief of Staff is speaking.

### Deployed
- Moved the interactive `#orb` from the disappearing initial welcome panel into a persistent station above the composer, available throughout both text and voice exchanges. Supports click/keyboard activation; retains listening and speaking animations.
- Browser `MediaRecorder` capture max 120,000 milliseconds with live `AnalyserNode` RMS speech detection. Once speech has actually begun, 3 seconds of measured silence automatically stops recording and launches transcription. Silence before the user begins is not treated as a completed question. Tapping the orb/mic manually remains supported and is a fallback if browser audio analysis cannot start.
- Dedicated, authenticated POST `/adapters/api/swade-bots/voice/transcribe` supports 12 MiB compressed microphone input and bounded 120-second conversion to mono 16k WAV. Inputs over 120 seconds are rejected, ffmpeg conversion is limited with a timeout and temporary-file cleanup, final WAV bounded to around 4 MB; local voice-server forwarding timeout was increased to 150 seconds. Spoken text is now bounded to 4,000 chars in transcript and chat, to avoid cutting off longer prompts; existing provider model rate/credit ceilings remain unchanged. Scoped exact-match nginx route grants 13 MiB client upload and 180-second response timeout ONLY to that transcription endpoint, preserving 64 KB for general `/adapters/` routes. Nginx syntax checked and safely reloaded; unauthenticated POST remains HTTP 401.
- User-initiated audio interruption remains immediate by tapping the orb/mic. For hands-free interruption, when the owner explicitly enters voice mode (taps orb or speaker test) and grants microphone permission, a cloned echo-cancelled microphone stream is retained while the assistant speaks. A temporary RMS analyser calibrates about 850 ms to room/speaker baseline, requires approximately 600 ms of sustained speech above a conservative threshold, cancels playback/pending speech and starts another recording. Barge-in counts as speech immediately, so 3 seconds of silence after an interruption can complete a short request. An accessible `Interrupt by speaking` toggle allows the owner to disable the retained microphone. Stop-audio also releases the mic; switching bots/page close releases microphone tracks. The bot has NO remote permission to activate the microphone outside a user-started voice session.
- This is **not yet assured full-duplex voice**: it is a microphone VAD/barge-in implementation in browser JavaScript. Apple Safari hardware behavior, acoustic echo suppression and false-interruption resistance require founder testing. If the device does not support simultaneous capture/playback, tapping the orb remains the supported fallback; do not claim otherwise. Audio capture is sent only to the on-prem SWADE voice transcription worker for the requested turn; no paid TTS or LLM changes.
