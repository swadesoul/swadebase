## 2. Purpose and successful outcome

Workscratcher analyzes sites and produces visual reconstruction materials. The released enhancement adds a path for an authorized operator to package actual source, original media, database schema/displayed content, configuration names and license evidence into one ZIP with verifiable completeness.

## 3. Features and evidence states

Existing source includes an analysis/reconstruction ZIP assembled from blueprints, component maps, asset manifests, prompt packs, parity reports and regenerated-asset references. That does not establish possession of a project's original source or database.

The published Complete handoff ZIP card at /visual-dna/download uses a shared browser/CLI builder. It checks pinned-source Git blob hashes, structured publication evidence, every descriptor and original, public-content row counts, names-only configuration, licensing, safe archive paths and SHA-256 checksums. Missing required inputs create a report instead of a delivery ZIP.

## 4. Customer journeys

Download the preparation template, supply the authorized files/evidence in a staging ZIP, and choose Validate and assemble delivery. A valid input enables Download complete ZIP; otherwise download the report and resolve its items. Existing reconstruction downloads remain available. The new card requires no blueprint selection or analysis-credit purchase. A signed-in manual download and iPad Safari session were not exercised; do not describe those as tested. The CLI accepts a directory or ZIP using npm run handoff:export -- --input /path/to/prepared-project --output /path/to/delivery.zip, writes a report, exits 2 for incomplete input and does not overwrite existing outputs.

## 6. Data and ownership

The new packaging path consumes explicitly supplied files locally; it does not query production, fetch private source or infer entitlement to customer records. Each content table requires an allowlist declaration, JSON array and exact row count. Auth, storage and vault system-schema data are rejected as content. Business-semantic review remains an operator duty; a local packager cannot discover an omitted table or decide whether arbitrary fields are private.

No Workscratcher schema migration or new database was required. Unlisted files and top-level data statements hidden in schema-only SQL are rejected; legitimate function-body SQL remains supported.

## 9. Media and storage

Supplied originals retain filenames and bytes. Descriptor originals are materialized beside descriptors and at source/public/__l5e/assets-v1 routes where applicable. Existing differing bytes must not be overwritten. Remote media references need original files and provenance. License status must be supported by supplied terms or an explicit owner statement; unknown/not-redistributable remains a blocker.

Limits are 256 MiB expanded, 128 MiB per file and 5,000 entries. Actual inflated bytes and CRC are checked sequentially. ZIP64, encryption, symlinks, traversal, case/file collisions, Git LFS pointers and unsupported submodules are rejected. Larger projects need a separately verified workflow and must not be truncated. Extensionless image URLs and font-stylesheet family queries retain distinct inventory coverage, including referenced font binaries.
