# SSSBrain repair connection — proposed bounded release

Status: prepared for explicit connection approval; not enabled. October 29, 2026, America/Chicago.

## Intended behavior
The founder can describe a fault in GPT Live or typed chat. SSSBrain reads the affected site's current Bible, verified repository files and service status, creates a concrete repair proposal, obtains the existing exact owner approval, then applies the approved change and checks the actual result. GPT Live and free voices share the same account, knowledge and action pathway.

## First release scope
Only independently verified mappings are eligible: swadesoul/sssbrain, swadesoul/swadebase, and swadesoul/swade-ecosystem-hub. The separate inventory of 143 repositories is discovery data, not an execution allowlist. Every additional site requires its repository, domain, deployment target and ownership to be verified before registration.

Repository inspection is bounded and refuses credentials and secret files. A proposed repair can create, edit or move at most eight ordinary source files, with exact base/blob verification and bounded content. It opens a draft pull request with the change, tests and rollback information. Merging or deployment remains a separate exact approved action. No arbitrary shell, wildcard repository permissions or database administrator interface is exposed to the model.

Service restarts must use the existing fixed helper and a verified service/container allowlist. A running process receipt is not an application health certificate. The known SSSBrain Coolify mapping is eligible only after server access and credentials are restored and validated. Unknown deployment targets remain blocked.

## Authentication and connections
Native requests must carry the original signed-in user's valid SWADEBASE JWT, recheck the current owner administrator role, and use narrow action scopes. The existing separate owner approval interface must approve the exact current proposal digest; the model cannot approve itself.

Connect a repository-scoped GitHub server credential for only the verified repositories and the existing Coolify server connection for verified deployment targets through protected server secret intake. Never paste a credential into chat or include it in a repository, browser bundle, logs, evidence or proposals. Existing chat-connected GitHub access is not automatically a server-side credential.
