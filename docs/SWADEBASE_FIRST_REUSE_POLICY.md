# SWADEBASE-FIRST ECOSYSTEM DEVELOPMENT POLICY

Founder directive, 2026-10-22. Applies to every Swade Soul ecosystem website and new feature.

Before designing or building: (1) inspect existing SWADEBASE services, database, schemas, functions, queues, workers, SDKs, media engines and shared modules, plus deployed runtime health; (2) check related sites including Black Tales, Maestro, RESING Lab and SSS Brain for proven reusable capabilities; (3) report verified available/partial/missing capabilities; (4) reuse existing working modules through secure, versioned, tenant-scoped adapters and preserve functionality; (5) implement only genuinely missing parts, local-first when practical, with explicit credits/cost approval; (6) test against baseline and in preview before production, ensuring rollback and no regressions. Do not duplicate a working feature or waste AI credits. A GitHub file does not prove a deployed service exists. Never inherit site-specific branding, creative/casting policy, pricing, payments or users when reusing code. Never expose keys or secrets. Do not alter existing production services simply to document this policy.

This policy should also be included in every new site's development handoff and project instructions; existing sites may be updated incrementally after checking their repository and instructions.
