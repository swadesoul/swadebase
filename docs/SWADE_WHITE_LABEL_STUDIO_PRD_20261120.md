Status: PLANNED / DOCUMENTED, not deployed

Owner approval: founder request to create universal SWADEBASE white-label capability.

## Purpose
Convert only founder-approved SWADEBASE registry sites into licensable customer-branded apps, embedded modules or enterprise deployments. Keep original product and customer tenants isolated. No default universal resale permission.

## Reuse
- Existing SWADEBASE registry, capability adapters, OnePass entitlements, private Postgres and GoTrue account identity; do not create duplicate auth/data.
- OATHLOOM existing project design contract, template catalog and revision/publish controls. Impeccable-quality design is a design requirement, not evidence of an installed provider.
- Existing SWOSTing hosting/onboarding/domain/cert and private app deployment workflow.
- SSS Brain read/plan/approval agent orchestration, audited jobs and no self-approval.
- Existing usage cost ledger, founder exemption, Stripe when enabled after separate payments testing, SWADE Sign legal contracts, B2 originals.
- Follow SWADEBASE Standing Rules including founder $0 application billing exemption; infrastructure/provider costs must still be metered internally.

## Operator workflow
1. Select source site from verified registry and check owner resale permission.
2. Read canonical Site Bible, repository commit, deployed feature inventory, integration adapters, regulated/license constraints and real cost data. Missing data = readiness blocked, not AI hallucination.
3. Generate source_manifest: site ID/version, eligible modules, API dependencies, theme assets, rights, data models, roles, cost and required contract.
4. Founder approves white-label feature allowlist, permitted customer plans, branding, customer domain, tenant tier and provider key policy.
5. Pricing advisor gathers timestamped competitor evidence and compares per-feature benchmarks; computes setup + monthly + annual + overage + hosted/BYOH costs with target margin. Founder's override wins; AI cannot activate prices.
6. OATHLOOM generates isolated tenant branding, customer onboarding, admin area and role-based pages using source_manifest and selected design contract; preserve upstream functionality.
7. SWOSTing preflight validates DNS, certificate, backup, model/provider policy, budgets, RLS and tenant data isolation, rolls out preview, runs acceptance and publishes only after explicit approval.
8. Grant scoped license and customer admin invitation; record immutable versioned audit and lifecycle events; optionally gift by zeroing customer charges for defined term/features.
9. Customer self-service brand/domain/pages, plan limits and product-specific permitted features; cannot alter founder/core permissions or other tenants.
10. Upgrades and revocations are reversible, versioned, tested and do not delete customer data by default.

## Pricing method
Cost floor = hosting + storage + AI/voice/video/compute + transactional API fees + payment fees + expected support + risk reserve. Suggested price = cost floor / (1-target gross margin). Compare source-verified competitor price normalized per site/seat/features; provide low/balanced/premium recommendations plus citations and checked date. Never fake market data. Offer one-time setup, monthly/annual, overages, BYO-provider, enterprise custom and founder-created gift. No live billing until checkout/webhook/entitlement/cancel tests pass.

## Acceptance gates

- Founder's exact feature allowlist and gift exemption

- SWOSTing tenant backup/restore and export/offboarding
- Registry and Site Bibles updated after verified code/deploy.
